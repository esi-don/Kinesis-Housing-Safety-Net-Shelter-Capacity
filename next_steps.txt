1. Official events schema
Obtain the SQL/schema specification from the project lead. Compare field types,
nullability, ID format, payload naming, consent fields and geography encoding.
Add compatibility validation and a migration/export adapter. Current SQLite is
deliberately provisional and follows the supplied report template.

2. Eviction features and NLP ownership
Confirm whether Pod 2 consumes a sanitized cohort feed or owns the LTB pipeline.
For a shared feed require observation date, actual publication date, geography,
coverage and extraction quality. For owned processing implement download
provenance, OCR where needed, automated NER plus masking rules for tenant and
representative names and exact unit numbers BEFORE analytical extraction.
Create labelled, independently reviewed redaction and extraction evaluation
sets; audit false negatives. Public availability is not a reason to retain PII.
Only then aggregate eviction indicators and test their incremental value using
as-of joins and the same chronological baseline comparisons.

3. Geographic alignment
Acquire official ward/neighbourhood boundaries and record boundary vintage.
Resolve public shelter addresses or identifiers against authoritative location
data. Preserve unmatched/ambiguous records, verify points-in-polygons and audit
changes in program locations. Train local models only where series are long and
complete enough. Citywide waiting-list counts do not establish ward demand.
Join census profiles with an explicit reference year and avoid attributing
shelter users' demographic characteristics from the site's neighbourhood.

4. Forthcoming RGI supply
Request project-level RGI completion or allocation data with unit counts,
delivery status, expected completion date, geography and publication history.
Distinguish subsidized units, RGI units, generally affordable units, available
allocations and total occupied stock. Add scheduled-delivery scenarios and
out-of-sample comparisons only when a defensible historical feature exists.

5. Waiting times
Obtain a published historical waiting-time series with a clear definition and
comparable reporting frequency. Build a separate target-specific baseline and
evaluation. A backlog/placement ratio is not an individual waiting-time model.
If data remain unavailable, agree an explicit scope adjustment with the lead.

6. Operational evaluation
Agree alert threshold, recipient, forecast issue time and action. Collect future
daily snapshots and actual release timestamps prospectively. Evaluate changing
capacity scenarios, probability calibration if probabilities are introduced,
false-alarm burden and advance warning time. Review prediction bands when
nominal coverage is poor. Investigate source omissions and reporting breaks.
