MODELLING AND FEATURE CONTRACT

Shelter grain
Source events: program, location (or explicit unknown), date, capacity type.
Analytical table: date, sector, compatible unit (beds or rooms), Toronto-wide.
occupied = OCCUPIED_BEDS for bed-based programs; OCCUPIED_ROOMS for room-based.
capacity = CAPACITY_ACTUAL_BED or CAPACITY_ACTUAL_ROOM, respectively.
SERVICE_USER_COUNT is deliberately not substituted for occupied rooms.
Aggregate rate = sum(occupied) / sum(capacity), never mean(program rates).
Invalid program numeric facts make that reported sector/day/unit total null.
Sector totals may change if the publisher changes program coverage. A missing
program row is not automatically interpreted as a closure.

Shelter features
occupied_lag0, lag1, lag7, lag14, lag28: matching calendar-day observations.
mean7, mean28: complete trailing windows ending at the observation cutoff.
std7, std28: sample standard deviation over those same complete windows.
capacity: actual capacity at the cutoff, not at the target date.
capacity_change7: current actual capacity minus capacity seven days earlier.
target_weekday: target day of week, Monday=0.
season_sin/cos: sine/cosine of target day of year, period 365.25 days.
All numeric shelter features must be present; there is no forward imputation.
Reindex to a complete daily calendar before constructing lags or labels.

Shelter targets and baselines
Separate direct model for h in {7,14,30} calendar days after the last observed
date t. The target is occupied(t+h), in the same unit and sector as the features.
The forecast horizon is relative to the last observed date; it is not a claim
about the exact publication or issuance hour. In live use the latest observation
may be a day old. Outputs retain both cutoff and target dates.
Persistence: occupied(t).
Weekday: latest observed day matching the target weekday, t-((-h) mod 7).
Boosting: predict occupied(t+h)-occupied(t), then add current occupancy and
floor the result at zero. Do not cap at capacity because that would erase the
very exceedance the project is intended to investigate.
Ensemble: equal average of boosting and persistence. It competes under exactly
the same chronological selection criterion; it is not automatically preferred.
Boosting settings are fixed in code, random_state=42, early_stopping=False.

Shelter selection and assessment
Use common calendar cutoffs across all sectors. Let T be the latest observed
date. Holdout origins start at T-90 days. Three development origin windows start
270, 180 and 90 days before that holdout start, each lasting 60 days.
At each development cutoff c, training origins are earlier than c and their
target dates must be <=c. This purges unavailable future labels. Require >=365
training examples and >=14 validation examples, plus >=730 source days and
coverage through T for a group to be considered.
Select the candidate with lowest pooled development MAE for each group/horizon.
Freeze the family selection. Fit at the holdout start and evaluate all eligible
holdout origins whose target is observed. Inputs update with each origin's
observations; the fitted holdout model does not update daily.
Finally refit using all eligible labels through T for the exported forecast.
Overlapping multiday forecast errors are correlated. Sample counts do not
represent independent experiments and no statistical superiority is claimed.

Uncertainty and alerts
Band radius = empirical 90th percentile (higher interpolation) of absolute
out-of-sample development errors of the selected family. Lower=max(0,p-radius),
upper=p+radius. No nominal coverage guarantee is made under serial dependence
or distribution shift. Holdout interval coverage and width are exported.
No probability of exceeding capacity is computed.
All exports are research-only. Each forecast includes a persistence reference,
selected-model and persistence holdout MAE, and observed interval coverage.
validation_status is fails_baseline if selected MAE exceeds persistence MAE;
otherwise fails_interval_coverage if coverage is below .90; otherwise
passes_initial_checks. This is a transparent assessment, not a new model
selection step or a claim of operational readiness. The original development
selection and all held-out failure cases remain in the evidence.
Live pressure flag = predicted occupancy / latest capacity >= threshold.
Default threshold=.95 is an illustrative planning choice requiring review.
Future capacity is assumed unchanged. Historical alert scoring uses realized
target capacity, so it is an assessment with hindsight capacity information,
not a complete simulation of live warning decisions or future closures.
Warning duration, crossing-time calibration and operational lead-time utility
are not evaluated in this version.

Waiting-list model
Source grain and modelling grain are citywide calendar quarters. Target is
the publisher's Total active waiting list, not individuals' time in queue.
Blank Q3 2026 is preserved in the events/clean table and excluded as a target.
No quarter is repeated into daily rows. All eligible quarters are on a full
quarterly grid. The last six published quarter positions form holdout origins.
Earlier development targets must end strictly before the holdout boundary;
origins whose targets cross the boundary are purged from selection.
Candidate forecasts: last value; last value plus h*(backlog(t)-backlog(t-4))/4;
Ridge(alpha=10) on lag0..lag3, latest change, four-quarter trend and target
quarter sine/cosine, predicting future change. Scaling is fitted inside each
training origin. Ridge requires >=8 fully observed labelled training rows.
Only candidates covering the maximum common set of development origins compete
for selection. Final holdout refits at each origin using labels observed by that
origin. Model-family selection remains fixed from earlier development results.
Quarterly small samples make validation fragile, especially at horizon four.
The source combines new and reactivated applications; no artificial split is
created. A balance residual is a diagnostic, not a known count of removals.

Temporal availability
availableat records snapshot download time, the first time this local pipeline
observed a fact. Observation dates are not publication dates. The source may
revise history. Current backtests use revised historical values as if observed
at their dates and must not be presented as a vintage-correct operational test.
External quarterly supply and eviction features are not used yet. Before adding
them, preserve actual publication times and join strictly as of the forecast
issuance timestamp. Never backfill a later publication into earlier origins.

Operational clustering
Last 90 observed days, >=60 valid program-days. Features: mean occupancy ratio,
sample standard deviation, fraction >=threshold, log(1+median capacity), and
relative capacity change across the window. Standardize and fit k=3 KMeans
separately by unit, n_init=20. Report silhouette and adjusted Rand agreement for
seeds 42 and 7. These are in-sample exploratory summaries, not predictive risk
validation. Locations are public shelter sites, not users' home neighbourhoods.
